I was going through my hard disk and came across
a 1994 #coders IRClog:

-Mrfbot- The output of your program should (only) show all prime numbers
-Mrfbot- between 1 and 1000 in numeral order, seperated by a space only.
-Mrfbot- All values should be in decimal format and no leading zeros allowed.
-Mrfbot- (output must be like: "2 3 5 7 11 13 17 19 23 ... 997")
-Mrfbot- All tricks are allowed. The smallest program wins.
-Mrfbot- Programs should return to DOS properly in a stable state.
-Mrfbot- Current smallest program so far is: 43 bytes by BitZero.

I was amazed by the size of this and tried to do the same for C.

I started with

p(i,k){for(k=2;k<i;k++)if(i%k==0)return 0;return 1;}
main(i){for(i=2;i<1000;i++)if(p(i))printf("%d ",i);}

and improved this to

main(i,j,k){for(i=2;i<1e3;i++){for(j=2,k=1;j<i;j++)if(i%j==0)k=0;if(k)printf("%d ",i);}}

and a local programmer Peter Adams improved this to 84 characters

main(i,j,k){for(i=2;i<1e3;i++){for(j=2,k=1;j<i;j++)k=k&&i%j;if(k)printf("%d ",i);}}

Can you do better?  No macro or #define cheating on the command line
or elsewhere.  I'm sure improvement is possible as Peter & I
are both inexperienced obfuscatory programmers, though I have
seen all the IOCCC prime programs.

Mainly I am interested in pure C, though partial credit is given for

(a) a system() call to the UNIX program factor
or
(b) a system() call to an APL program where the size of the 
C program + the APL program < 84 bytes (This is easy!)
