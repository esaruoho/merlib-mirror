## Introduction to Systems Analysis

|  |  |
|----|----|
| **Term** | **Definition** |
| System | A group of related procedures |
| Data | Consists of basic facts, the raw material. |
| Information | Information is the finished product after data has been processed. |
| Processing | Transformation of data input into accurate, meaningful information that is required. |
| Input | Data is input by workers or machines to an Information System. |
| Output | Information is output by the Information System. |
| Information Systems Components | Software, hardware, data, people and procedures. |
| Application | An Information System can also be called an Application. Application software produces information needed by users. |
| Hardware | Computer platforms and peripherals used for input, processing and output. |
| Software | System and Application software, or programs control the IS environment, local or networked, OTS or legacy, includes the Operating System. |
| Legacy System | How the system worked before proposed or implemented changes through Systems Analysis. |
| Derived Information | All information is either produced directly, or derived, which would imply some function performed upon the data to produce a new synthesis. |
| End Users | Includes employees, customers, vendors or others who directly interact with the Information System. |
| Corporate Culture | A set of beliefs, rules, traditions, values, and attitudes that define a company's personality and influence its way of doing business. |
| BIS | A Business Information System could be production-oriented, service-oriented, or a combination of both. |
| Subsystems | A larger IS may be broken into a series of smaller subsystems. |
| EDI | Electronic Data Exchange is one standard interface between different Information Systems. |
| Interdependent IS | Output from one may be Input to another. |
| Boundary | A not always clear-cut interface between two systems or processes. This will effect the Scope of a project. |
| Vertical Market IS | Application software is said to be vertical when it is for a highly specialized need or requirement. |
| Transaction processing | Another term for operational systems. |
| MIS | Management Information Systems generate timely and accurate information for all management levels. |
| EDP | Electronic Data Processing were one form of early operational systems. |
| DSS | Decision Support Systems help make business decisions by analysing internal or external data. A typical example is a What-If Analysis. |
| What-If Analysis | Using a model, determine the best course of action based upon hypothetical data and presumptions. The better the model, the more precise the prediction, of course. |
| EIS | Executive Information Systems combines the features and capabilities of both MIS and DSS, but with more flexibility and support for unstructured decision-making. |
| ESS | Executive Support Systems support the information requirements of top-level managers and their need to make unstructured decisions. |
| Structured Decisions | Occur regularly, have predefined information requirements and result in predetermined actions. |
| Unstructured Decisions | Do not occur regularly, cannot be predicted, and whose information requirements cannot be predefined. |
| Semistructured Decisions | A combination of structured and unstructured decisions. A set of predefined inputs and outputs do not exist. |
| Expert System | Computers capable of simulating human reasoning and decision-making by combining a knowledge base with inference rules. Cannot actually use common sense or intuition. |
| Knowledge Base | A stored database of known and reliable information. |
| Inference Rules | Determine how the Knowledge Base is used to reach decisions, operating within preprogrammed limits |
| Fuzzy Logic | Not actually whatever drove me to think this was a good idea, but rather one which allows logical inferences to be drawn from imprecise relationships. |
| AI | Artificial Intelligence is beyond the scope of this page to define, but a Fuzzy Logic System may, depending on your definition, be an example. |
| OAS | Office Automation System is a now archaic term. |
| Empowerment | Enabling people to handle tasks and make decisions that were assigned previously to higher organizational levels. |
| Organizational Levels | Operational personnel, Lower Management, Middle Management and Top Management pyramid scheme. |
| Operational Personnel | Operational personnel perform repetitive functions with well-defined procedures. |
| Lower Management | Direct day-to-day operations, make appropriate decisions and take correction actions where applicable. Highly structured. |
| Middle Management | Focus on longer range tactical planning, usually at least a month to a year. |
| Top Management | Focus on even longer range strategic planning, hopefully ensuring the company will survive and grow in the future. |
| Tactical Planning | Plans to allocate company resources to achieve organizational objectives. |
| Strategic Planning | Establish the overall company mission, policies, goals and future product lines. |
| Exception Reports | Identify variances from set targets which might require action. |
| SDLC | Systems Development Life Cycle is a series of steps used to build an information system. These include Planning, Analysis, Design, Implementation, Operation and Support. |
| Systems Request | Identifies the IS and describes the desired changes or improvements. |
| Preliminary Investigation | Critical step in the planning phase of SDLC, begun with a Feasibility Study which determines if it is appropriate to continue. |
| Preliminary Investigation Report | The final report to management on a Preliminary Investigation of a Systems Request, including recommendations. |
| Feasibility Study | The Feasibility Study is a part of the Preliminary Investigation. |
| End Product | The output or a deliverable. |
| Prototype | Early working version of an information system. This can speed up SDLC process objectives. |
| Systems Analyst | Investigates, analyzes, designs, develops, installs, evaluates and maintains a company's IS. May plans projects, develop schedules, or estimate costs. Must conduct meetings. deliver presentations, write memos, emails and documentation. |

### Determining Requirements

**Term**

**Definition**

Requirements Determination

When what has to be done is known <u>exactly</u> , the algorithm built, the prototype completed, the Scope of the project known, only then can the analysis of those requirements and an evaluation of alternatives be understood in proper context for successful implementation.

Fact-finding

Who, what, why, where, when, how, how much and "Are we there yet".

Systems Requirements

A characteristic which must be included in an IS to satisfy business requirements and be acceptable to Users.

Reverse Engineer

An attempt to find out how the original system functioned before it was modified. "This is not SPEEA retrospeak for career path".

Algorithm

"Mr. Vice President singing the Blues".

Retrospeak

"Talking about that last Millennium"Next year will be Y2K++.

TBS

Tailored Business System. (Vertical market)

Outputs (Systems Requirements)

Defined requirements to serve as a benchmark to measure acceptability of finished system.

Inputs (Systems Requirements)

Defined requirements to serve as a benchmark to measure acceptability of finished system.

Processes (Systems Requirements)

Defined requirements to serve as a benchmark to measure acceptability of finished system.

Timing (Systems Requirements)

Defined requirements to serve as a benchmark to measure acceptability of finished system.

Control (Systems Requirements)

Defined requirements to serve as a benchmark to measure acceptability of finished system.

Volumes, Sizes and Frequencies

Required information about the current system examined for it's impact on proposed system.

Interview

Knowledge of a company's formal and informal structures will help determine who to interview. After establishing the objectives of and preparing for the interview, conduct, document and evaluate the interview. How very simple!

Informal Structures

In an informal structure, some people have more influence or knowledge than would appear on an Organizational Chart.

Formal Structures

A company's Organizational Chart.

Organizational Chart

A company's pyramid scheme of responsibilities, whereby those at the top receive more perquisites, gratuities, privileges, bonuses, benefits, advantages, opportunities, rights, concessions, dispensations, license and freedoms than those who actually produce the product.

Hawthorne Effect

From 1920, it was noticed that increasing short-term productivity improvements could be made merely by watching the workers, whether conditions were made better or worse!. One local boring hairspace company has pushed this envelope to new heights with it's policy of low morale equals low self-esteem equals lower pay! After the worker is used up, they're disposable! This simple little formula led to another discovery, that the more workers are laid off, the higher the stock price of the company goes up! This enables the top cells of the pyramid to retire a few days early, and the workers enjoy the retraining! The only problem was illogical STRATEGIC THINKING! With no workers, there were no consumers. Oh, except a few who retired early, quite wealthy.

Questionaire

Document containing a number of standard questions.\
1) Brief, clear, user-friendly instructions (for all anticipated questions).\
2) Keep in logical order, from easy to complex, simple words.\
3) Test the questionaire before distributing.\
4) Do not lead response (give clues to expected answers).\
5) Limit use of open-ended questions.\
6) Limit negative issue questions, like job security.\
7) Include a General Comments section at the end.

Systematic Sample

For instance, selects every n<sup>th</sup> customer file for review.

Stratified Sample

For instance, selects x customer files in y categories for review.

Random Sample

For instance, selects <u>any</u> x number of customer files for review.

Site Visit

Observe a system in use at another location.

Documenting Research

1\) Record or preserve the data!\
2) Record it as soon as it is obtained.\
3) Organize it to best be able to locate needed data quickly.\
4) The database must be in a form generally understood.\
5) Keep examples of DFDs, flowcharts, sample forms, and screen captures.\

PIM

Personal Information Managers are <u>software</u> file cabinets, calandars, schedulers, to-do lists, phone dialers, secretaries, diaries, archives, etc., all rolled into one environment.

Application Suite

A software platform which is built to integrate the functions of word processing, spreadsheets, databases, presentation and others, which <u>may</u> use templates, scripts, macros, batch files or Agents to present a common interface to the worker, no matter which computer they happen to be using.

CAD-CAM

Computer-Aided-Design and Computer-Aided-Manufacturing

JAD

Joint Application Development is a popular systems development technique, which creates a task force of users, managers and IS together during SDLC phases.

Task Force

Committee empowered to accomplish a given objective.

RAD

Rapid Application Development reduces time required to design new IS, the all-new "lean" data system!

O-O

Object-Oriented systems development is built to a system model based on objects and their interaction, rather than on processes and data flows.

Object

Abstract entity which the system may interact with, which has attributes, or "properties", and "methods", or events.

Class

Group of objects with similar attributes.

Subclass

"Junior college".

<td>Second Normal Form (2NF)</td>
<td>A record is in the Second Normal Form if it is in 1NF and if all fields that are not part of the Primary Key are dependent on the entire Primary Key. If any field in a 1NF record depends on only one of the fields in a combination Primary Key, then the record is not in 2NF. A 1NF record with a Primary Key that is a single field is automatically in 2NF.</td>
</tr>
<tr>
<td>Third Normal Form (3NF)</td>
<td>A record is in the Third Normal Form if it is in 2NF and if no Non-Key Field is dependent on another Non-Key Field.</td>
</tr>
<tr>
<td>Conversion of Normalization Forms</td>
<td>The three normalization forms constitute a progression in which a record in 1NF is better than one that is unnormalized. but a record in 2NF is better yet, and a record in 3NF represents the best design.<br />
<strong>To convert from unnormalized to 1NF:</strong>
<ul>
<li>Expand the Primary Key to include the Key of the repeating group</li>
<li>Therefore, the new Primary Key may quite likely be a combination of other key fields</li>
</ul>
<strong>To convert from 1NF to 2NF:</strong>
<ul>
<li>Create a new record design for each field in the Primary Key</li>
<li>Then, create new record designs for all combinations of Primary Key fields taken two at a time, three at a time and so on until there exists a record with the entire original Primary Key</li>
<li>Next, for each new record, designate a field (or combination of fields, as a Primary Key</li>
<li>Finally, place each of the remaining fields with its appropriate primary key, which is the minimal key upon which it depends, and remove any record that has had no additional field placed into it</li>
</ul>
<strong>To convert from 2NF to 3NF:</strong>
<ul>
<li>Remove all fields from the 2NF record that depends on another nonkey field</li>
<li>Place these into a new record that has the other field as a Primary Key</li>
</ul>
Normal forms beyond 3NF exist, however are rarely used in most business-oriented systems.<br />
Design to reduce redundancy. This is what normalization is all about.</td>
</tr>
<tr>
<td>Steps in DataBase Design</td>
<td><ul>
<li>Create initial ERD</li>
<li>Assign all data elements to Entities</li>
<li>Create 3NF designs for all records, taking care to identify all Primary, Secondary and Foreign Keys.</li>
<li>Verify all Data Dictionary Entries</li>
</ul></td>
</tr>

## Systems Design

- Output Design
- Input Design

- System Architecture

**Term**

**Definition**

System Architecture

Logical design and physical structure of a system, including hardware, sofware, design, and processing methods.

Environment

A particular combination of hardware and systems software. See Platform.

Platform

A particular combination of hardware and systems software. See Environment.

Processing Methods

- Online Processing
- Batch Processing
- Combined Online and Batch Processing
- Centralized Processing
- Distributed Processing

Online Processing

Handles transactions when and where they occur and gives output directly to user.

- Interactive
- Avoids delays
- Allows dialog with user
- Increases productivity
- Available continuously
- More expensive than batch processing
- Effects of downtime far more disruptive

Batch Processing

Data is collected and processed in groups, or batches, possibly in non-peak computing hours.

- Cost effective
- Less vulnerable to system disruption
- Less intrusive to normal operations

Combined Online and Batch Processing

A Point Of Sale (POS) terminal is one example. Most IS will continue to use a combination of online and batch processing to maximize on the strengths of each.

Centralized Processing

Typically involves mainframe and terminals located at one central location to provide information for an entire enterprise.

Distributed Processing

Consists of **data resources that are accessible at many locations**, allowing tasks to be performed by decentralized computers instead of a central computer system.

Data Communication Network

A collection of terminals and other equipment that uses communication channels such as telephone lines or the Internet to share data.

Multi-User Environment

A networked system with many users.

Stand-alone Environment

A non-networked system with one (at a time) user.

**DDBS**

Distributed Database Management System is data stored in more than one location.

File Server

Computer delivering data across various local and wide area networks.

Client-Server Architecture

Data and processing can be shared throughout the organization.

LAN

Local Area Network connects a group of personal computers in a limited area to a server that connects them and allows them to communicate efficiently and securely.

WAN

Wide Area Network connects a group of LANs into a network that can span the globe. The Internet is a WAN.

Network

Allows hardware, software and other data resources to be shared to reduce expenses and provide more capability to users.

Hierarchical Network

One computer, typically a mainframe, controls the entire network. Individual satellite processors control lower levels of processors and devices.

Bus Network

A singel communication path connects the mainframe computer, minicomputers, workstations and peripherals. A failure in one workstation may not necessarily affect other workstations.

Star Network

One central processor, or hub with one or more workstations connected to it in a star-pattern.

Ring Network

Many computers connected in a ring pattern, with data flowing in only one direction.

EDI

Electronic Data Interchange is one protocol for communicating in business computing.

Network Topology

Refers to the type of networked system architecture, such as Bus, Star, Ring, etc.

Suspense File

A common method for handling corrections by creating an error transaction file, known as a **Suspense File**.

**Logical Deletion**

When a system cannot allow deletion of a record, for archival purposes, yet want to disallow it from live, current data, some administrators use a flag for one field which then marks that record as logically deleted.

Processing Functions

- Data Input
- Data Validation
- Data Updating, or file maintainance
- Data Sorting and Filtering
- Data Reporting

Log Files

A copy and/or documentation of modified master file records stored in special places for troubleshooting or recovery.

- Also known as a "Journal" file
- Contains a copy of each record as it appears **before** modification
- Contains a copy of each record as it appears **after** modification
- Used in recovery programs or procedures to ensure restoration of accurate data
- Data Reporting

File Retention

The length of time a file needs to be archived.

- Master files and table files are permanent and should be retained for the life of the system
- Transaction files, backup files and others are determined by a combination of processing and legal requirements
- Many in IS use a generation cycle concept,such that at least 3 backups are available at all times - Grandfather, Parent and Child backup files

Processing Support

- Backup and Recovery
- File Retention
- Restart (after correcting a problem)
- Start-up (transition to new system)

Checkpoint and Program Status Indicators

A way to restart interrupted batch processing, without having to necessarily begin from the original starting point.

Software Design

- Use a separate update program to maintain each Master File
- Provide a validation program for each update program that does not perform it's own validation
- Reduce the number of report programs if possible
- Identify any programs required to perform special processing

Program Documentation

- Program Identification, including Name, Version, Department, Author, dates, etc.
- Purpose of the program - brief description
- Files input, output, printed or updated
- Processing requirements and limitations

Object-Oriented Design

Bottom-up approach which stresses data, not data flows.

System Design Specification

A detailed document which presents the complete design for a system along with detailed costs, staffing, scheduling, etc.

- Management Summary
- System Components Detail
- Environmental Requirements
- Implementation Requirements
- Time and Costs Estimates
- Appendices

System Components Details

The complete design for the new system with all relevant source documents.

<td>Performance</td>
<td>System performance directly affects users who rely on it to perform their job functions. Current system performance should be monitored by IS staff, anticipating future needs.</td>
</tr>
<tr>
<td>Response Time</td>
<td>Overall time between a request for system activity and the delivery of the response. Measured between the time a user clicks on a command button and the time the final output is available for use, the response time is affected by the system design, capabilities and processing methods such as data communication factors.</td>
</tr>
<tr>
<td>Turnaround Time</td>
<td>Measures the efficiency of central computer operations.</td>
</tr>
<tr>
<td>Throughput</td>
<td>Measures the efficiency of the computer itself, or a data communications network.</td>
</tr>
<tr>
<td>Capacity Planning</td>
<td>A process that monitors current activity and performance levels, anticipates future activity, and forecasts the resources needed to provide and sustain desired levels of service.</td>
</tr>
<tr>
<td>What-If Analysis</td>
<td>A process whereby one variable (or more) is changed to measure the effect on other elements.</td>
</tr>
<tr>
<td>System Obsolescence</td>
<td>A system is obsolete when its functions are no longer required by users or when the platform becomes outmoded or is no longer cost-effective to operate and maintain.</td>
</tr>
<tr>
<td>Top Six Signs of System Obsolescence</td>
<td><ul>
<li>Maintenance history documentation shows steadily increasing adaptive and corrective maintenance</li>
<li>Operational costs or execution times are rapidly increasing and routine perfective maintenance does not reverse or slow the trend</li>
<li>A new off-the-shelf (OTS) application becomes available that provides the same or additional services more efficiently, faster, or less expensively than the current system</li>
<li>Technology becomes available which offers the same or additional functions more efficiently</li>
<li>Maintenance changes or additions are difficult and expensive to perform</li>
<li>Users request significant new features to support business requirements</li>
<li><strong>Bill Gates needs a new space station!</strong> (<em>Just kidding, Bill!</em>)</li>
</ul></td>
</tr>
<tr>
<td>Examples of<br />
<strong>Perfective Maintenance Projects</strong></td>
<td><ul>
<li>Additional high-speed memory</li>
<li>Macros or Scripts to handle repetitive tasks</li>
<li>Upgrade modems to latest technology</li>
<li>Replace network cabling with fiber optics</li>
<li>Create a code module that compresses data files before net transmission</li>
<li>Rewrite a program in a new nonprocedural language</li>
<li>Redesign a graphical interface to provide greater flexibility</li>
<li>Reorganize program modules to interact more efficiently</li>
<li>Develop a library of reusable code modules</li>
<li>Create multiple desktop settings so several users can share the same PC</li>
<li>Replace older stroage devices with high-speed disk technology</li>
<li>Use OOP for application development</li>
<li>Convert slower batch processing tasks to online procedures</li>
<li>Replace older technology components with newer technology piecemeal throughout the system.</li>
</ul></td>
</tr>
