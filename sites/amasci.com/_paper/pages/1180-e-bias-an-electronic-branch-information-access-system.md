    While Internet Banking has become a buzz word in the Banking industry not all Banks are comfortable allowing remote access to their databases. In addition, many Banks have legacy systems which makes it difficult or un-economical to offer Internet Banking.
<p>e-BiAS allows Banks to allow remote Internet access to information from their existing legacy system without any change in their legacy systems or allowing remote access to their existing databases. In addition, data from third party databases such as Electronic Securities, Exchange and Interest Rates etc. can be made available to customers of a Branch.</p>
<div data-align="center">
<p><img src="images/man_computers.jpg" width="244" height="233" /></p>
<div data-align="center">
&#10;</div>
</div>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Secure</strong></p>
<p>E-BiAS uses Testkeys, Asymmetrical Encryption, Symmetrical Encryption and hardware dongles in addition to Server based passwords and SSL making it an extremely secure system.</p>
<p><strong><img src="images/red-bullet.gif" width="10" height="10" /></strong> <strong>Database Isolation</strong></p>
<p>As E-BiAS replicates data from a Branch's legacy system into its isolated database, a Branch's legacy database remains inaccessible to remote information requests.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Fast</strong></p>
<p>An e-BiAS transaction takes place in seconds.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>User Defined Information Access</strong></p>
<p>Users can define exactly what information is to be made available to specified persons accessing data.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Flexible Authorization Automation</strong></p>
<p>Users can define authorization automation such that specific requests be automatically responded to while other requests require manual officer authorization.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Dual Client</strong></p>
<p>E-BiAS has both a fat client and thin client allowing a Branch to decide on whether it wishes to implement a convenient live web server or a cost effective email based server.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Currency independent</strong></p>
<p>E-BiAS allows access to information in any number of currencies.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>XML Compliant</strong></p>
<p>E-BiAS messages are XML compliant easy interfaces to existing legacy systems as well as uploads to systems being used by parties requesting information.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Operating System Independent</strong></p>
<p>Being written in pure Java code, the interface module allows interface to legacy systems operating under virtually any operating system be it UNIX, Windows, Linux, OS/400 or DOS.</p>
<p><img src="images/red-bullet.gif" width="10" height="10" /> <strong>Interface to TEST</strong></p>
<p>E-BiAS interfaces to Bankstar's TEST system allowing Testkeys as an additional security measure.</p></td>
