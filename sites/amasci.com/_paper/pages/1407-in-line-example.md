<span id="analysis"></span> **Analysis**

- <span id="a1"></span>**Line:** General\
  **CSS Issues:** [In-line Styles](../syntax/inclusion/inline.htm)\
  **Description:** Note that this example seems more cluttered than the External and Embedded CSS examples. This is because the style information is mixed in with the document content. Even with this rather small quantity of style rules, the size of the resulting document is larger than either the External or Embedded CSS examples. This method can be useful if a small number of styles are applied to individual tags, but it quickly becomes unwieldy (as seen here) when style rules are applied to multiple tags. The lack of classes to address multiple selectors is a big liability to this method.
- <span id="a2"></span>**Line:** [5](#e5)\
  **CSS Issues:** [Pseudo-classes](../syntax/pseudo/pseudoclass.htm)\
  **Description:** We are using the HTML BODY attributes to control hyperlink behavior. The lack of anchor pseudo-classes makes this necessary. The BGCOLOR and TEXT attributes for the BODY tag could be used here as well, but we are trying to use in-line styles in as many situations here as possible, so just ignore that point. =)
- <span id="a3"></span>**Line:** [6](#e6)\
  **CSS Issues:** [Multiple Selectors](../syntax/selectors/selectors.htm#sel), [Multiple Declaration Shorthands](../syntax/declaration.htm#decgroup)\
  **Description:** The style attribute here sets many properties for the H1 tag. much of this style information is also used on the SPAN tag in line 31. In using the in-line method we lose the advantage of selector grouping that classes offer.
- <span id="a4"></span>**Line:** [8](#e8)\
  **CSS Issues:** [Pseudo-elements](../syntax/pseudo/pseudoelement.htm)\
  **Description:** We are using the SPAN tag within the P element to simulate a 'first-line' pseudo-element used in the document-level and external style sheet examples. In-line styles do not allow for the possibility of attaching styles to virtual tags, so the effect must be simulated with a real tag. Note that the hack in this example is crude, and can not be counted on to always produce a true 'first-line' effect that is created by the virtual pseudo-element structure.
- <span id="a5"></span>**Line:** [10](#e10)\
  **CSS Issues:** [Pseudo-elements](../syntax/pseudo/pseudoelement.htm)\
  **Description:** Here we have nested DIV tags. The innermost DIV tag pair is used as in the previous line to achieve a pseudo-element effect (a 'first-line'.) The first line is quite easily determined in this case by the early placement of the BR tag to end the first line. The end of the 'first-line' is not as easily determined in the previous line because the original line as designed would flow to well over one line under most browser resolutions and screen sizes. Remember that line breaking decisions for an end user can not be pre-determined - if you keep this in mind you will be far less perturbed by the inevitable variations that occur from browser to browser.
- <span id="a6"></span>**Line:** [11](#e11) / [29](#e29)\
  **CSS Issues:** [Pseudo-elements](../syntax/pseudo/pseudoelement.htm)\
  **Description:** Another little hack is used in these instances in the absence of the ability to use the 'first-letter' pseudo-element. Since we can easily determine what constitutes the first letter in these and most cases, we can assign a SPAN with the desired style information to our intended 'first-letter'. Given the choice, it seems preferable to use the pseudo-element when possible, as it does not use extra tags. Drawback: few browsers support the pseudo-elements yet.
- <span id="a7"></span>**Line:** [12](#e12)\
  **CSS Issues:** [Multiple Selectors](../syntax/selectors/selectors.htm#sel)\
  **Description:** The External and Embedded CSS examples use a separate rule to set the background information for several tags. Since that can not be done here, it must be specified again and again for each element instance. This has the effect of creating duplicate style statements as well as some very busy HTML tags.
- <span id="a8"></span>**Line:** [13](#e13)\
  **CSS Issues:** [Contextual Selectors](../syntax/selectors/element.htm#descendent), [In-line Styles](../syntax/inclusion/inline.htm)\
  **Description:** A special style is given to the EM tag. In other CSS examples this is accomplished by contextual selectors (which can not be used in the case of in-line styles.) Because there is only one instance of this tag nesting situation in these examples, neither method has any drawbacks.
- <span id="a9"></span>**Line:** [16](#e16) / [18](#e18) / [22](#e22) / [26](#e26)\
  **CSS Issues:** [Multiple Selectors](../syntax/selectors/selectors.htm#selectgroup),[Special Properties](../syntax/declaration.htm#decshorthand)\
  **Description:** We are setting several properties on multiple HTML tags here. Now we begin to see the great power in the brevity of HTML class structures. We have to repeat our style information not just twice, but FOUR times in order to cover all occurrences. Clearly this leads to increases in file size and are a detriment to download time.
- <span id="a10"></span>**Line:** [21](#e21)\
  **CSS Issues:** [Inheritance](../topics/inherit.htm)\
  **Description:** Special properties are assigned to this particular item in the list. The nested SPAN tag will inherit the FONT-SIZE and FONT-STYLE properties assigned to this LI.
- <span id="a11"></span>**Line:** [25](#e25) / [26](#e26) / [27](#e27) / [28](#e28) / [31](#e31)\
  **CSS Issues:** [Inheritance](../topics/inherit.htm)\
  **Description:** These are just normal, mundane inline CSS statements applied to BLOCKQUOTE, DIV, P with SPAN tags nested inside them. The SPAN tags will inherit the property values assigned to the parent tags unless those properties are also specified for the SPANs as well.
- <span id="a12"></span>**Line:** [30](#e30)\
  **CSS Issues:** [Shorthand Properties](../syntax/declaration.htm#decshorthand)\
  **Description:** Uses shorthand properties on the P tag. Using 4 shorthands in this case accomplishes same work using an abbreviated syntax as 15 of the regular individual properties. When using in-line styles, we need to conserve all the space we can.
- <span id="a13"></span>**Line:** [33](#e33)\
  **CSS Issues:** [Inheritance](../topics/inherit.htm), [Cascading Rules](../topics/cascade.htm)\
  **Description:** This use of '!important' on style assignments is unique here in this document. It will indicate to the browser that the rule must be used in preference to a normal rule set for this tag situation specified using another method (using a reader's own style sheet for example.) This is a good way to guarantee that a crucial style element in your page survives the uncertainty of a Cascading Order calculation. This control should not be abused however, as it reduces the control the reader has over their browsing environment (a reader may have, for instance, valid *physical* reasons for their viewing environment settings.)
- <span id="a14"></span>**Line:** [34](#e34)\
  **CSS Issues:** [Pseudo-classes](../syntax/pseudo/pseudoclass.htm)\
  **Description:** In other examples we use a pseudo-class to assign styles to a particular state of this individual anchor. Because state dependent style assignments are only possible through External or Embedded style sheets, we can do nothing to the tag in this case.
