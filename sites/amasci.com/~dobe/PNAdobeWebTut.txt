 XHTML Introduction

 Start of this page 

 XHTML 
 is very similar to HTML but with a few more 

 rules
 .
 That's because it's really is an XML document and although it does not have to be

 valid
 .
 , it does have to be 

 well-formed
 .
 !
 How XHTML differs from HTML
 A DTD is MANDATORY. See DOCTYPE 

 A reference to the XML namespace in the <html > element is REQUIRED!
 See <html > 
 XHTML and XML are case sensitive! <html > and <HTML > are NOT the same! 
 ALL XHTML elements MUST be lower-case! 
 This does not apply to attributes, only tags. 
 Use <head > not <HEAD >! 

 Every opening element MUST have a corresponding closing element. 
 An empty tag:
 Contains no text to be displayed. 
 Exists mainly for display and setting attributes. 
 Is an exception to rule 5 and has a special syntax. 
 Examples: <br /> and <hr /> 
 Note : leave a space before the ending " />" 

 <head > and <body > element sets are REQUIRED! 
 The first element in the <head > section MUST be the <title > element. 
 ALL attributes values MUST be contained within " quotation marks ". 
 No attribute may be minimized. For example, 
 <input checked="checked"> is REQUIRED! 
 To avoid using certain coding symbols such as < and &, use the 
 reserved character references, 
 some of which are named, because of common usage.

 Any content using the CDATA syntax is unparsed by the browser: 

 <script > 
 <&#91;!CDATA&#91; 
 ...unescaped script content goes here... 
 &#93; &#93; > 
 </script > 

 Attribute values must be denoted within mandatory "double-quotes"! 
 Tags may not nest. 
 Attribute values must not be minimized! 
 The <pre> container element may not contain: 
 <img>, <object>, <big>, <small>, <sub> , or <sup> child elements. 
 Forms may not nest inside of other forms. Close elements in the proper order. 
 Use character codes from the 
 ISO Latin-1 Character Set 
 where appropriate, for instance, a Nonbreaking space is written as: "& n b s p ;" and a "&" symbol must be written as "& a m p ;". 
 For the Strict DTD in XHTML: 
 "<!--Comments are no longer used.-->" 
 "Any use of CSS should use all lower case lettering." 
 "Any use of JavaScript should be done through external JavaScripting, except 
 if using unparsed Character Data Section format:" 
 <script language="JavaScript type=text/javascript"> 
 <![CDATA[ 
 document.write("Yo, Dobe!"); 
 ]]> 
 </script> 
 Also, JavaScripts are no longer commented out.
 but these are NOT required for the Transitional DTD . 

 For the Strict DTD in XHTML: 
 "<!--This Comment style is no longer used.-->" 
 <[!CDATA[This is the new comment style for Strict DTD XHTML]]>

 Merely Suggestions:
 The name attribute essentially replaces the id attribute, use both and make them identical.

 <div name="identifier00" id="identifier00"> 
 ...content... 
 </div > 

 The lang and xml:lang attributes both specify the language, but the
 xml:lang attribute has priority. 
 Find the definitive standards, syntax and solutions at 
 http://www.w3.org/ 

 Check and double-check document well-formedness! 
 Verify your document has a single root element! (Declarations don't count!) 

 XHTML Links

 Start of this page 

 Any word, picture or other object, such as a button, 
 may act as a trigger to an event. In this case, 

 Links . to a specific line in a specified file is easily 
 accomplished in modern advanced browsers . 
 This could be extended to a given character in an XML document. 
 Hyperlinks, depending on the syntax used, will display the contents of a file in: 

 A new browser window, leaving the current contents undisturbed 
 Replace the contents of the current browser 
 Replace the contents of a current given frame 

 With a few simple commands such as: 

 <a href="some_local_file.htm"> Click here </a> 
 >

 cause the words: "Click here" will cause an event which will display "some_local_file.htm" in a target frame or new window. 

 XHTML Frames

 Start of this page 

 XHTML Frames are really fun, even though they 
 are somewhat in disfavor. Some people rabidly dislike them, but used for 
 navigation, I don't see anything wrong with them myself. Below you'll find a 
 few examples of different things you can do with frames and how it's done. 

 Frame Pages 

 enable multiple pages to be displayed in one browser window. As author, you 
 have complete control over which file will be displayed where, what size the 
 frame window should be, etc. and can be controlled programmatically as well as 
 at design time. The Frames tutorial explains all this visually, don't miss it! 
 NOTE: 
 Documents using elements <

 frame 
 > or 
 <

 frameset 
 > should use special DTD in the header: 

 <?xml version="1.0" encoding="UTF-8"?> 
 <!DOCTYPE html 
 PUBLIC "-//W3C// DTD XHTML 1.0 Frameset //EN" 
 "http://www.w3.org/TR/xhtml1/DTD/xhtml1-frameset.dtd"> 

 <html xmlns="http://www.w3.org/1999/ xhtml " xml:lang="en" lang="en"> 
 <head>Meta-information 
 </head> 
 <frameset> 
 <frame> 
 </frame> 
 </frameset> 
 </html> 

 Frames are defined in a single starting page which requires NO BODY . 
 If you use frames, use the Frameset DTD header above or it won't work! 
 The Frameset DTD is identical to the Transitional DTD except for frame and frameset elements. 
 The iframe element does NOT require the Frameset DTD, only MSIE. 
 Rows and Columns are defined in the frameset. 
 Source file to be displayed in a given frame element called by src="" 
 target="" may work but is deprecated. Use src=""

 Changes to <!DOCTYPE> in MSIE 6.0 

There are now dual CSS rendering engines, which helps Internet Explorer comply with W3C standards.
One line of HTML code, (known as a Document Type Definition , or DTD) 
tells MSIE 6 that it should use its ' classic" rendering engine ', considered more 'forgiving', 
or the new standards-compliant rendering engine. 
 Control whether the browser works the old way or the new way using different DTDs! 

<!-- MSIE 6 'classic engine' <!DOCTYPE> template: --> 
<!-- If your page doesn't use a DOCTYPE, or if you use a DOCTYPE that includes the 
words 'Transitional', then MSIE 6 will use the classic engine. --> 
 <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.0 Transitional//EN"> 

<!-- MSIE 6 'standards compliant rendering engine' <!DOCTYPE> template: --> 
<!-- Or, if a URL is specified where a DTD can be found, 
 or if a DOCTYPE doesn't include the word 'Transitional' or includes the word 'Strict',
 then this is triggered: 
--> 
 <!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.0 Transitional//EN" 
"http://www.w3.org/TR/html4/loose.dtd">

 The Anchor elements require the href= , id= or name=

 Text and/or images may be contained within an anchor.

 To embed an XML Data Island into an HTML Page, use the XML element within the HTML document.
This syntax is valid for Internet Explorer 5. Replaces overloading the HTML <script> element, 
which has been deprecated. 
There are two syntactically correct ways of using the XML element within the HTML document: 

The XML data can exist inline, surrounded by XML open and close tags. 

 <XML ID="XMLID"> 
 <XMLDATA> 
 <DATA>TEXT </DATA> 
 </XMLDATA> 
 </XML> 

The XML element can have a SRC attribute, the value of which is the URL for an XML data source. 

<XML SRC="http://localhost/xmlFile.xml"></XML>

The XML element is present in the HTML Document Object Model . It is in the all collection and is seen by the browser as just a regular node. The XML data within the XML element can then be accessed by calling the XMLDocument property on the XML element. 

The XMLDocument property returns the root node of the XML within the XML element or the root node of the XML referenced by the value of the SRC attribute. From this root, the XML data island can be navigated using the XML document object model. The following function returns the data from the data island with the ID of "XMLID". 

function returnXMLData(){ 
 return document.all("XMLID").XMLDocument.nodeValue; 
 } 

The XML element can also be referenced by ID alone. For example, the following function has the identical functionality as the previous example. 

function returnXMLData(){ 
 return XMLID.documentElement.text; 
 } 

Note that because the XMLDocument property was not used, the documentElement property will need to be called to retrieve the root element of the XML.

(The 
 script element was overloaded to have this 
 functionality in previous browsers.) 

Example: 

This example uses the XML element to define a simple XML data island that can be embedded directly into an HTML page.

 <XML ID="oMetaData"> 
 <METADATA> 
 <AUTHOR>John Smith</AUTHOR> 
 <GENERATOR>Visual Notepad</GENERATOR> 
 <PAGETYPE>Reference</PAGETYPE> 
 <ABSTRACT>Specifies a data island</ABSTRACT> 
 </METADATA> 
 </XML> 

This script example retrieves the text contained within the ABSTRACT field of the data island. 

 var oNode = oMetaData.XMLDocument.selectSingleNode("METADATA/ABSTRACT"); 
 alert(oNode.text);
